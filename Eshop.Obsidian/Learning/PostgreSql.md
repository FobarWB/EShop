# PostgreSql

Related: [UsePostgreSql](../Decisions/UsePostgreSql.md), [Services](../Services/Services.md).

## Key ideas

- **Roles.** Users and groups are one concept, a role; `LOGIN` lets a role connect. The app uses its own role `eshop`,
  not the `postgres` superuser. Since PostgreSQL 15 only the database owner (or granted roles) can create tables
  in `public`, so `eshop` owns the database.
- **pg_hba.conf** decides who may connect and how (`scram-sha-256` = password, `trust` = no password).
  A forgotten superuser password is reset by switching localhost to `trust`, setting `\password`,
  restoring the file and reloading (`Restart-Service` or `SELECT pg_reload_conf()`).
- **Identifiers.** Unquoted names are folded to lower case: `Products` and `products` are the same, `"Products"` is not.
  Hence snake_case without quotes. Identifiers are limited to 63 bytes; longer names are truncated.
- **Transactional DDL.** `CREATE TABLE` / `CREATE INDEX` run inside a transaction and roll back on error,
  so a failed migration leaves no half-created schema.
- **Tightening a column.** `ALTER COLUMN … SET NOT NULL` fails if any row is `NULL`, so existing `NULL`s are updated first.
  It scans the whole table under an `ACCESS EXCLUSIVE` lock; on large tables add `CHECK (col IS NOT NULL) NOT VALID`,
  then `VALIDATE CONSTRAINT` (weaker lock), then `SET NOT NULL` uses the validated check and skips the scan.
- **Identity columns.** `GENERATED BY DEFAULT AS IDENTITY` is backed by a sequence. Inserting explicit ids
  does not move it: after loading data run `setval(pg_get_serial_sequence('t', 'id'), max(id))`,
  otherwise the next insert fails with a duplicate key. `nextval` is not rolled back, so gaps in ids are normal.
  The sequence never reuses values: deleting the last row or a failed insert leaves a gap, by design
  (concurrent inserts get ids without waiting for each other). Do not "fix" gaps: an id is a surrogate key,
  and a reused id would match stale references in logs, caches, URLs or messages; `MAX(id) + 1` also races.
  A human-facing gapless number (e.g. an invoice number) belongs in a separate column.
  For local test data only: `TRUNCATE carts, cart_items RESTART IDENTITY` empties the tables and restarts numbering.
- **Time.** `timestamp without time zone` stores a calendar date and time; `timestamptz` stores an instant
  (UTC inside, shown in the session time zone). Npgsql maps `DateTime` to `timestamptz` and requires `Kind=Utc`.
- **Money.** `numeric(p,s)` is exact; the `money` type depends on `lc_monetary` and is not recommended.
- **Literals.** `bytea` hex: `'\x0A1B…'`; booleans are `true`/`false` (an integer is not cast automatically);
  ISO dates `'1996-07-04'` do not depend on `DateStyle`.

- **Foreign key errors.** The `ON DELETE` rule decides the error code of a rejected `DELETE`: `NO ACTION` (the default)
  checks at the end of the statement and can be deferred to `COMMIT` (`DEFERRABLE`), error `23503 foreign_key_violation`;
  `RESTRICT` checks at once and cannot be deferred, error `23001 restrict_violation`. Both mean "still referenced".
  Here `cart_items → products` is `RESTRICT` (EF `DeleteBehavior.Restrict`), `order_details → products` and
  `products → categories` are `NO ACTION`, `cart_items → carts` is `CASCADE`
  (`SELECT confdeltype FROM pg_constraint WHERE contype = 'f'`).
- **LIKE patterns.** `ILIKE` is a case-insensitive `LIKE`. In a pattern `%` is any text and `_` any one character,
  `\` escapes them: user input goes through `Regex.Replace(name, @"[\\%_]", @"\$0")` before `%…%`, otherwise a search
  for `%` matches every row. A bound parameter prevents SQL injection, not wildcards. `%text%` cannot use a B-tree index;
  a trigram index (`pg_trgm`) would, should the table grow.
- **Paging.** `OFFSET … LIMIT …` without `ORDER BY` has no defined order: a row may land on two pages or on none.
  Order by a unique key. `OFFSET n` still reads and discards n rows; keyset paging (`WHERE id > @last ORDER BY id LIMIT n`)
  does not, and stays stable while rows are inserted.
- **Backup and move.** `pg_dump -Fc` writes a compressed custom-format archive of one database (schema, data,
  `__EFMigrationsHistory`); `pg_restore` loads it, can restore selected objects and run in parallel. Roles live outside
  a database (they are cluster-wide), so they are not in the dump: create them first, restore with `--no-owner`.
- **MVCC and `xmin`.** An UPDATE writes a new row version; the system column `xmin` holds the id of the transaction that
  wrote it, so it changes on every update and serves as a free version number (`SELECT xmin, * FROM products`).
- **Read Committed allows lost updates.** Two transactions that read a value, compute and write it back both succeed;
  the second overwrites the first. Guards: a version check (`WHERE xmin = …`), an atomic `SET x = x - 1 WHERE x >= 1`,
  `SELECT … FOR UPDATE`, or Serializable isolation with retries.
- **NULLs in unique indexes are distinct** (by default; `NULLS NOT DISTINCT` since PG 15): many rows with `(NULL, NULL)`
  do not violate a unique index. A violation is `23505` with the index name in `constraint_name`.
- **Adding a nullable column without a default** only changes the catalog: no table rewrite, instant on any size.

## Applied in this project

- PostgreSQL runs in Docker since #47 ([Docker](Docker.md)); the data of the former Windows service was moved with
  `pg_dump -Fc` → `pg_restore`.
- Schema from EF Core migrations, data from [db/northwind-data.sql](../../db/northwind-data.sql), loaded with `psql -f`.
  The script sets `\set ON_ERROR_STOP on`, `client_encoding = 'UTF8'` and runs in one transaction.
- EF Core takes an advisory lock (`pg_advisory_lock`) while applying migrations, so parallel app instances do not
  apply the same migration twice. The first `database update` logs a failed `SELECT` from `"__EFMigrationsHistory"`:
  expected, the table does not exist yet.
- `psql` on Windows: the console code page (866) differs from 1251, so non-ASCII input may break; `chcp 1251` helps.
  The prompt ends with `#` for a superuser and `>` otherwise; `-#` means an unfinished statement (`\r` clears it).
- Useful `psql` commands: `\l`, `\dt`, `\d <table>`, `\du`, `\password`, `\q`. GUI: pgAdmin 4
  (eshop → Schemas → public → Tables; Tools → Query Tool).

## Open questions

- The former Windows service used the collation `English_world.1251`; the container uses `en_US.utf8` (glibc),
  as CI does. `ORDER BY` on text may differ from the old database; ICU collations would make it independent of the OS.
- Northwind dates have no time part: `DateOnly` + `date` would be more precise than `DateTime` + `timestamp`.
