# PostgreSql

Related: [UsePostgreSql](../Decisions/UsePostgreSql.md), [Services](../Services/Services.md).

## Key ideas

- **Roles.** Users and groups are one concept, a role; `LOGIN` lets a role connect. The app uses its own role `eshop`,
  not the `postgres` superuser. Since PostgreSQL 15 only the database owner (or granted roles) can create tables
  in `public`, so `eshop` owns the database.
- **pg_hba.conf** decides who may connect and how (`scram-sha-256` = password, `trust` = no password).
  A forgotten superuser password is reset by switching localhost to `trust`, setting `\password`,
  restoring the file and reloading (`Restart-Service` or `SELECT pg_reload_conf()`).
- **Identifiers.** Unquoted names are folded to lower case: `Products` and `products` are the same, `"Products"` is not.
  Hence snake_case without quotes. Identifiers are limited to 63 bytes; longer names are truncated.
- **Transactional DDL.** `CREATE TABLE` / `CREATE INDEX` run inside a transaction and roll back on error,
  so a failed migration leaves no half-created schema.
- **Identity columns.** `GENERATED BY DEFAULT AS IDENTITY` is backed by a sequence. Inserting explicit ids
  does not move it: after loading data run `setval(pg_get_serial_sequence('t', 'id'), max(id))`,
  otherwise the next insert fails with a duplicate key. `nextval` is not rolled back, so gaps in ids are normal.
- **Time.** `timestamp without time zone` stores a calendar date and time; `timestamptz` stores an instant
  (UTC inside, shown in the session time zone). Npgsql maps `DateTime` to `timestamptz` and requires `Kind=Utc`.
- **Money.** `numeric(p,s)` is exact; the `money` type depends on `lc_monetary` and is not recommended.
- **Literals.** `bytea` hex: `'\x0A1B…'`; booleans are `true`/`false` (an integer is not cast automatically);
  ISO dates `'1996-07-04'` do not depend on `DateStyle`.

## Applied in this project

- Schema from EF Core migrations, data from [db/northwind-data.sql](../../db/northwind-data.sql), loaded with `psql -f`.
  The script sets `\set ON_ERROR_STOP on`, `client_encoding = 'UTF8'` and runs in one transaction.
- EF Core takes an advisory lock (`pg_advisory_lock`) while applying migrations, so parallel app instances do not
  apply the same migration twice. The first `database update` logs a failed `SELECT` from `"__EFMigrationsHistory"`:
  expected, the table does not exist yet.
- `psql` on Windows: the console code page (866) differs from 1251, so non-ASCII input may break; `chcp 1251` helps.
  The prompt ends with `#` for a superuser and `>` otherwise; `-#` means an unfinished statement (`\r` clears it).
- Useful `psql` commands: `\l`, `\dt`, `\d <table>`, `\du`, `\password`, `\q`. GUI: pgAdmin 4
  (eshop → Schemas → public → Tables; Tools → Query Tool).

## Open questions

- The database collation is the Windows locale `English_world.1251`; in Docker (Linux, ICU or `en_US.utf8`)
  `ORDER BY` on text may differ.
- Northwind dates have no time part: `DateOnly` + `date` would be more precise than `DateTime` + `timestamp`.
